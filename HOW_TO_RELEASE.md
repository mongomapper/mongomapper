# How to release MongoMapper

The official release path is `script/release` (`rake release -- <flags>` just wraps it).
In the examples below, `X.Y.Z` is the new version (e.g. `0.19.0`) and the tag is `vX.Y.Z` (e.g. `v0.19.0`).

Steps marked **HUMAN** need a person; automation (including AI agents) must stop and hand off there.

Key files:

- `lib/mongo_mapper/version.rb`: `MongoMapper::Version = 'X.Y.Z'`
- `CHANGELOG.md`: one `## X.Y.Z - YYYY-MM-DD` section per release
- `CONTRIBUTORS`: generated by `etc/git-rank-contributors`
- CI: GitHub Actions workflow "Ruby" (`.github/workflows/ruby.yml`)

## 1. Prepare the release PR

Precondition: master is up to date and the working tree is clean.

```sh
git checkout master && git pull --ff-only origin master
git checkout -b prepare-X-Y-Z-release
```

- In `CHANGELOG.md`, rename the `## Unreleased` section to `## X.Y.Z - YYYY-MM-DD`, then add a new commented
  `<!-- ## Unreleased ... -->` template above it. List every PR merged since the last tag
  (`git log --merges --oneline vPREVIOUS..master`), credited to the original author, in the existing format:
  `- PR-NNN Name <email> Description`, grouped under `### Enhancements:` / `### Bug Fixes:` / `### Doc Fixes:`.
- In `lib/mongo_mapper/version.rb`, set `Version = 'X.Y.Z'`.
- Optional: run `rake update_contributors` (stages `CONTRIBUTORS`) or `rake update_contributors_and_commit`.
  Only keep the result if the diff looks sensible.

```sh
git commit -am "Prepare X.Y.Z release"
git push -u origin prepare-X-Y-Z-release
gh pr create --base master --title "Prepare X.Y.Z release"
```

Check: `script/release --dry-run` on the branch shows `version.rb (X.Y.Z) matches CHANGELOG.md heading`.
It will also report "not master" and refuse, which is expected.

## 2. Merge the PR (HUMAN)

Check: CI is green on the PR (`gh pr checks <PR>`).
**HUMAN:** a maintainer reviews, approves, and merges the PR.

## 3. Verify master

```sh
git checkout master && git pull --ff-only origin master
grep Version lib/mongo_mapper/version.rb
grep -m1 -E '^## [0-9]+\.[0-9]+\.[0-9]+ - ' CHANGELOG.md
gh run list --workflow ruby.yml --commit "$(git rev-parse HEAD)"
```

Check: both commands show `X.Y.Z`, and the "Ruby" run for the merge commit is `completed` / `success`.
Wait if it's still in progress.

## 4. Dry run

```sh
script/release --dry-run
```

Check: every precondition prints `ok:`, CI shows `CI passed`, and the plan lists `git tag vX.Y.Z`,
`git push origin vX.Y.Z`, `gem push mongo_mapper-X.Y.Z.gem`, and the GitHub release notes.
A dry run doesn't build a gem, tag, push, or publish anything. It exits non-zero if a real run would refuse.

## 5. Release for real (HUMAN)

**HUMAN:** approval to run the real script (not `--dry-run`) is required. The script needs a TTY and asks
`[y/N]` before each irreversible step: tag create, tag push, gem push, and GitHub release.

```sh
script/release                     # asks whether to create a GitHub Release
script/release --github-release    # create the GitHub Release (still confirmed)
script/release --no-github-release # skip it
```

The script:

1. Checks preconditions: clean tree, on master, master == origin/master after `git fetch`, version.rb
   matches the top dated changelog heading, and `vX.Y.Z` doesn't exist locally or on origin.
2. Checks that the "Ruby" workflow succeeded for HEAD via `gh`. If `gh` is missing, you must confirm manually.
3. Runs `gem build mongo_mapper.gemspec`. It does not run the test suite; CI already did.
4. Runs `git tag vX.Y.Z` (lightweight, matching existing tags), then `git push origin vX.Y.Z`.
   It never pushes master.
5. Runs `gem push mongo_mapper-X.Y.Z.gem`. **HUMAN:** this requires a RubyGems owner of `mongo_mapper`
   with 2FA. Enter the OTP when prompted, or run with `GEM_HOST_OTP_CODE=123456 script/release`.
   Never commit or hardcode credentials.
6. Optionally runs `gh release create vX.Y.Z` with the changelog section as notes. The gemspec's
   `changelog_uri` points at this release page.

If the script aborts partway, read the output: steps that already ran (e.g. a pushed tag) are not undone.
Finish the remaining steps by hand rather than re-running from scratch.

## 6. Verify the release

```sh
git ls-remote --tags origin vX.Y.Z          # tag exists on origin
gem info mongo_mapper --remote              # shows X.Y.Z (or check https://rubygems.org/gems/mongo_mapper)
gh release view vX.Y.Z                      # only if a GitHub Release was created
```

## 7. Optional: mongomapper.com post (HUMAN, manual)

If mongomapper.com still needs a post, add `_posts/YYYY-MM-DD-release-X-Y-Z.md` on the `gh-pages` branch
and push it. This step isn't automated. Example:

```md
---
title: MongoMapper X.Y.Z Release
layout: post
author: Scott Taylor
---

MongoMapper X.Y.Z has been released.

See the [changelog](https://github.com/mongomapper/mongomapper/blob/master/CHANGELOG.md) for full details.
```

Check: the post appears on mongomapper.com within a few minutes.
